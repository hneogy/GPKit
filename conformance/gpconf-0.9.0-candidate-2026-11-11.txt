How it was run (GPKIT this checkout, CORPUS a checkout of gpconf's tree, DATA a folder holding fixtures/<case>/raw/):

  swift build
  cd CORPUS && python3 -m gpconf run --root . --data DATA --no-fetch-hint -v \
    --cmd "'$GPKIT/.build/debug/gpkit-gpconf' --epoch vallado parse {fmt}" \
    --vectors-cmd "'$GPKIT/.build/debug/gpkit-gpconf' --epoch vallado vectors" \
    --write-cmd "'$GPKIT/.build/debug/gpkit-gpconf' --epoch vallado write" \
    --json report.json
  python3 $GPKIT/tools/check_gpconf.py report.json --gate

Reading it:
- With the vallado epoch every case passes but the data check, which runs no parser; the propagation tier passes
  within its tolerance, which is how gpconf grades a propagator (a plain pass there means the reference's numbers
  to the bit). tools/check_gpconf.py --gate: met.
- With the exact epoch, the default, the same but sgp4-ver-propagation, which fails on one set by 4.11e-6 km.
- The case grades Vallado's own verification output, and that output carries the epoch his reader makes, so it is
  judged here in the vallado epoch, which the adapter declares to gpconf ({"epoch": "vallado"}). The exact epoch
  stays GPKit's default, and the line-for-line comparison with tcppver.out is
