Streamed batch propagation (Propagator.streamStates, branch v2-streaming) against the batch that keeps a run: a
day at one-minute steps of 10,000, 20,000 and 40,000 made-up element sets, with the most memory each process held.
Run on 2026-11-10 (UTC), 16:33:59Z to 16:37Z, on a Mac17,4 (Apple M5, 10 cores: 4 performance, 6 efficiency,
16 GB), macOS 27.2.1 (26B131), Apple Swift version 6.4.2, release build, branch v2-streaming on GPKit 1.3.0. Each
run was started only with the one-minute load at 12 or less, no xcodebuild and no simulator round. The load at each
start and end is printed; it was 7.7 to 12.4, a busy Mac, so compare these runs with one another and not with
benchmark-2026-11-10.txt.

How it was run, each in a process of its own so that its peak memory is its own:

  swift run -c release --package-path tools/benchmark benchmark --count 10000 --stream
  swift run -c release --package-path tools/benchmark benchmark --count 20000 --stream
  swift run -c release --package-path tools/benchmark benchmark --count 40000 --stream
  swift run -c release --package-path tools/benchmark benchmark --count 40000 --stream --budget 2
  swift run -c release --package-path tools/benchmark benchmark --count 40000 --stream --budget 32
  swift run -c release --package-path tools/benchmark benchmark --count 40000

The element sets are the tool's made-up constellation; no provider's data is in them. Each time is the median of 5
runs after one to warm up. Before timing, --stream checks the stream against one propagator at a time, to the bit,
on three instants of every set; a planted fault there stopped it ("the stream does not give what one propagator
gives", exit 1).

What it shows: with the default 8 MiB budget the stream added 12, 11 and 15 MB to what the propagators held at
10,000, 20,000 and 40,000 sets, where the batch's day held 3,386 MB at 40,000. At the same load the two ran at the
same speed, 55 and 56 ns a state. The proposed bound for phones, at most 24 MB added at any count with the default
budget, is met at every count measured. The propagators' own 174 MB at 40,000 sets (with the tool's input text and
read sets) is outside it, and is the next issue (docs/design/streaming-2.0.md).
