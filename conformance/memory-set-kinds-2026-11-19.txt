What a propagator costs with two kinds of made-up element set, plain and full, at 10,000 sets.

Run on 2026-11-19 (UTC), 01:05Z, on a Mac17,4 (Apple M5, 10 cores: 4 performance, 6 efficiency, 16 GB), macOS 27.2.1
(26B131), Apple Swift version 6.4.2, release build, at the GPKit 2.0.2 preparation (tools/benchmark with --sets).
The load average was 1.8 at the start. Each stage ran in a process of its own, twice.

How it was run, the same on any machine:

  swift run -c release --package-path tools/benchmark benchmark --memory check-pieces --count 10000 --sets full
  swift run -c release --package-path tools/benchmark benchmark --memory STAGE --count 10000 --sets KIND

  STAGE: none, text, file, all, sets-only, pieces (as in memory-split-2026-11-10.txt); KIND: minimal, full.

The element sets are made up, by the rule in tools/benchmark, the same on every run. No provider's data is in them.
- minimal (the default): the 17 CSV columns the other records use.
- full: the same orbits, with every keyword of CCSDS 502.0-B-3's OMM that GPKit reads filled in. That is the header
  (CCSDS_OMM_VERS, CREATION_DATE, ORIGINATOR), the metadata (CENTER_NAME, REF_FRAME, TIME_SYSTEM,
  MEAN_ELEMENT_THEORY) and the spacecraft parameters (MASS, SOLAR_RAD_AREA, SOLAR_RAD_COEFF, DRAG_AREA, DRAG_COEFF),
  with a 24-character name (a TLE's line 0), an 11-character international designator, and every number written to
  12 decimals. Its lengths come from the format.

Before measuring, check-pieces confirmed that the full sets read 1,000 at a time give what they give whole: 10,000
element sets, 0 refusals, the same values in the same order. Every run read 10,000 sets and refused none.

Sizes, the same for both kinds: Propagator 1,368 bytes, ElementSet 472, the SGP4 state and gravity 896.

Footprints in MB at the end of each stage, everything still held (runs 1 and 2), and the most memory held:

  stage        minimal       peak          full          peak
  none         2.2   2.2     7.5   7.5     2.2   2.2     7.5   7.5
  text         5.8   5.8    11.0  10.9    10.1  10.1    15.4  15.4    (1.4 and 3.6 MB of UTF-8)
  file        35.3  35.3    40.8  40.8    58.8  58.8    64.4  64.4
  all         48.4  48.4    53.9  53.9    71.9  71.9    77.5  77.5
  sets-only   15.9  15.9    21.4  21.4    24.1  24.0    29.7  29.7
  pieces      25.8  25.8    31.3  31.3    33.9  33.9    39.6  39.6

Bytes a set, less an empty process, from the means of the two runs:
- the propagators kept alone ("pieces"): 2.36 KB a set minimal, 3.17 KB full;
- the element sets kept alone ("sets-only"): 1.37 KB minimal, 2.19 KB full;
- so the propagator's own part (pieces less sets-only) is 0.99 KB minimal and 0.98 KB full: the SGP4 state is the
  same, and the 0.8 KB between the kinds is in the element sets' own allocations (their text: names, ids and the
  keywords kept in otherKeywords).

So a propagator costs about 2.4 KB a set with plain made-up sets and about 3.2 KB with every OMM keyword GPKit reads
filled in. Neither is a bound on a real file: a file can carry columns beyond OMM's, or longer text, and GPKit keeps
those too.
